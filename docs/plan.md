# Project Plan

## Project Name

Jazmine Reynolds Personal Portfolio Website

## Project Overview

This project is a two page personal portfolio website created to introduce Jazmine reynolds, share my professional interests, and display selected academic and digital projects. The website will include a homepage, and About Me page, one shared CSS stylesheet, a README file, and three planning documents. The completed project will be stored in a public GitHub repository and published using GitHub Pages.

## Project Goals

- Create a professional two page personal portfolio website.
- Build a homepage names 'index.html'
- Build an About Me page names 'about.html'
- Use one external stylesheet names 'style.css' for both pages.
- Include working navigation links betwen both pages.
- Include links to selected projects, including the gamification knowledge base and Canva projects.
- Create clear project documentation in Markdown.
- Publish the completed website through GitHub Pages.

## Risk Analysis: TAME Framework

### Risk 1: Not Having enough time

I have school, work, and family responsibilites that could limit the time I have to work on this project.

- **TAME Strategy:** Mitigate
- **Plan:** I will break the project into small tasks and work on it a little at a time before the deadline.

### Risk 2: HTML and CSS mistakes

I may make an error in my HTML or CSS that causes part of the website to not display correctly.

- **TAME Strategy:** Mitigate
- **PLan:** I will save my work often and check the website in my browser after making changes.

### Risk 3: Broken links

The links between my Homepage and About Me page, or links to my projects may not work.

- **TAME Strategy:** Mitigate
- **Plan:** I will click every link before I submit the project to make sure they work correctly.

### Risk 4: GitHub Pages problems

GitHub Pages might not publish my website right away, or I might have trouble with the settings.

- **TAME Strategy:** Mitigate
- **Plan:** I will publish the website early and check the GitHub Pages settings before the due date.

### Risk 5: Losing files or changes

I could accidently delete, overwrite, or lose a project file.

- **TAME Strategy:** Transfer
- **PLAN:** I will use GitHub and GitHub Desktop to save versions of my work by making regular commits.

### Risk 6: Adding too much to th eproject

I might want to add too many pages or advanced featured that are not required. 

- **TAME Strategy:** Eliminate
- **Plan:** I will follow my scope statement and keep the project limited to two pages with beginner level HTML and CSS.

### Risk 7: Unexpected problems

Personal responsibilites, illness, or technology issue could affect my schedule.

- **TAME Strategy:** Accept
- **Plan:** I will adjust my schedule if needed, focus on the most important requirements first, and ask for help if I have a major problem.
